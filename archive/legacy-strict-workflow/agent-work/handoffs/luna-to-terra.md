## Behavior and decisions

- Root package is private ESM, declares Node `>=24.18.0 <25`, pnpm `11.25.0`, and exact development dependencies TypeScript `5.9.3` and Vitest `3.2.4`.
- pnpm workspace globs are only `apps/*` and `packages/*`; nine child packages are discovered. Moodle and test boundaries are not workspaces.
- Shared TypeScript config uses strict NodeNext/ES2022 settings and the approved safety flags. Each child extends it and contains only `export {};` source behavior.
- Root commands are `pnpm --recursive --stream run typecheck`, `vitest run --passWithNoTests`, and `pnpm --recursive --stream run build`. Lint/format are explicitly deferred.

- `.env.example` contains only safe local defaults/placeholders; `.env` is ignored. `LOG_LEVEL=debug` is represented but not consumed by application code.

## Deviations and environment notes

- Initial Corepack/pnpm and Docker commands were blocked by sandbox permissions exactly as anticipated in the requirements. Both passed after the approved escalation route; no fallback package manager or image was used.
- pnpm 11 initially reported `ERR_PNPM_IGNORED_BUILDS` for esbuild. Only esbuild was reviewed and approved with `pnpm approve-builds esbuild`; the resulting sole committed lifecycle allowlist entry is `allowBuilds.esbuild: true`.
- The first immediate PostgreSQL readiness probe raced container startup and returned “no response.” A bounded health wait then reached healthy, and the subsequent readiness and pgvector checks passed.
- Validation ran without a local `.env`, so Compose's directory project name was `ai-platform` and the preserved volume was `ai-platform_postgres_data`. The safe environment example still declares `COMPOSE_PROJECT_NAME=moodle-agent-poc` for developers who choose to copy it.
- The nested project is not a standalone Git repository, so `git check-ignore`/diff-based validation was unavailable; read-only file and ignore-rule checks were used instead.

## Known limitations

- There are no application tests or runtime behavior yet; the no-tests Vitest allowance is intentional for Phase 0.
- No lint/format tool is selected.
- Docker service validation depends on local Docker availability and registry access.
- The named volume contains local disposable state; `docker compose down --volumes` remains an explicitly destructive reset and was not run.
