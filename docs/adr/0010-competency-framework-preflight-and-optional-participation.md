# Competency Framework preflight and optional Course participation

Status: Accepted

Ticket 24 deliberately blocked Moodle Competency materialization when no eligible Framework was explicitly available. That safeguard becomes a poor user experience on a Moodle site with no Competency Framework at all, and deriving Competency Candidates before discovering that state also wastes model tokens and Teacher review effort. The system will therefore perform a deterministic Competency Framework Preflight before any Competency Candidate derivation: use a valid configured Framework when available; otherwise reuse the canonical Default Competency Framework; and only when the site has no visible Framework at all, idempotently bootstrap the system-owned Default Framework through Moodle APIs using the system context and Moodle Default competence scale. This bootstrap is infrastructure provisioning, not Course or Competency materialization.

Competency participation is optional at Course level. If a usable Framework cannot be established after a confirmed no-Framework result for a supported provisioning-prerequisite failure, the Course may record Competency Participation as BYPASSED and continue without deriving or materializing Competencies. A Teacher may also explicitly bypass Competencies even when a Framework is available. Connectivity, authentication, permission, disabled-subsystem, or otherwise indeterminate preflight failures are not treated as absence and must not silently bypass; they remain actionable check failures. Candidate decisions are preserved across participation changes. Final Course approval revalidates the selected Framework, and Execute must still assert the approved snapshot is current. This intentionally supersedes Ticket 24's no-auto-create/no-framework hard-stop behavior while preserving its Teacher-authority and Execute-only Course/Competency materialization boundaries.
